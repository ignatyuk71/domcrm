# Витрати

Сторінка `/expenses` доступна тільки активному власнику через «Налаштування →
Бухгалтерія → Витрати». API й усі вкладення перевіряють роль на сервері.
Наявна фіскалізація `/finance` працює окремо.

## Логіка обліку

- Витрата містить загальну суму зобов’язання, валюту, категорію, отримувача,
  необов’язкову групу й термін оплати. До неї належить один або кілька платежів.
- «Додати оплату» створює витрату та повний платіж разом. «Запланувати» створює
  зобов’язання; у його деталях можна вносити часткові оплати.
- «Оплачено» і діаграми рахують проведені платежі за датою оплати.
  «Залишилося оплатити» рахує неоплачений залишок витрат із терміном у вибраному
  періоді. Сума зобов’язання не додається повторно до платежів.
- Рахунки є джерелами списання, а не банківськими інтеграціями або балансами.
  Перекази між власними рахунками не потрібно вносити як витрати.
- Гроші зберігаються цілими копійками. Для USD/EUR/PLN/CNY власник указує курс
  гривні за одну одиницю валюти; курс конкретного платежу зберігається назавжди,
  доки його явно не виправлять. У гривневих підсумках використовується округлення
  кожного платежу до копійок. Для майбутніх оплат використовується очікуваний курс.
- Оплата рекламного кабінету є рухом грошей. Спожитий рекламний бюджет, окупність
  і прибуток ця сторінка не обчислює. Погашення позики можна віднести до окремої
  категорії й групи, не створюючи повторно той самий борг.

## Квитанції

До кожного платежу можна вручну додати до 10 PDF/JPEG/PNG/WebP, кожен до 10 МБ.
Розпізнавання тексту відсутнє. Сервер перевіряє фактичний MIME та розширення,
використовує випадкові імена й приватний диск `local`. Копії не потрапляють у
`public/` або `storage/app/public/`. Вміст файлів дедуплікується в межах платежу.

Ліміти PHP `upload_max_filesize`, `post_max_size`, `max_file_uploads` і розмір
запиту вебсервера мають дозволяти ці вкладення (10 МБ на файл, до 110 МБ на запит).

Завантаження файлів виконується після підтвердження збереження платежу. Помилка
вкладень не створює другу оплату: форма зберігає вибрані файли для повтору.
Видалення вимагає окремого підтвердження. Помилки показуються через спільний toast,
а незбережені зміни мають захист від випадкового закриття.

## Узгодженість та перевірки

Зміни платежів серіалізуються блокуванням витрати. Поле `version` захищає від
перезапису змін з іншої вкладки. Ключі ідемпотентності захищають повторні POST
створення витрат/платежів. CSV містить усі відфільтровані оплати, незалежно від
пагінації, із захистом від інтерпретації тексту як формул.

```bash
php artisan test tests/Feature/Expenses tests/Feature/Auth/RbacTest.php
npm test -- resources/js/crm/pages/expenses
npm run build
```

## Локальний огляд

Міграції модуля: `2026_09_21_000000_create_expenses_tables.php` і
`2026_09_21_000100_add_content_hash_to_expense_receipts_table.php`.

```bash
php artisan expenses:demo
```

Команда додає лише «Міжнародна доставка»: одну витрату, одну оплату й одну PDF-квитанцію.
Повторний запуск не дублює демозаписи. Автоматично під час міграцій вона не виконується.
Типово дозволена лише в `local` і для локальної БД. За явним рішенням власника
на сервері можна вручну виконати `php artisan expenses:demo --force`.
Зразки позначені як демонстраційні й не підтверджують реальних платежів.
