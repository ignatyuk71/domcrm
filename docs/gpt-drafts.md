# Незалежний модуль GPT: ручні чернетки

Сторінка власника: `/settings/gpt` → «GPT · чернетки» в налаштуваннях.

Ресурси модуля збираються окремо в `public/build/gpt`; основний manifest і ресурси інших сторінок залишаються незмінними. Загальний `npm run build` також виконує цю додаткову збірку.

Модуль має власні інструкції, клієнт OpenAI Responses API, чергу `gpt-drafts`, пам’ять тестових діалогів і журнали. Немає підписки на Inbox, змін вебхуків, перемикання провайдера, відправлення через Meta чи створення замовлень. Рекомендація `handoff` залишається частиною чернетки.

## Встановлення

Після перевірки змін застосувати лише нову міграцію модуля:

```sh
php artisan migrate --path=database/migrations/2026_10_27_120000_create_gpt_draft_module_tables.php
npm run build:gpt
php artisan queue:work database --queue=gpt-drafts --timeout=75 --tries=20
```

GPT використовує окрему чергу `gpt-drafts` через підключення `database`, незалежно від загального `QUEUE_CONNECTION`. За потреби власне підключення задається `GPT_DRAFT_QUEUE_CONNECTION`; команда обробника має відповідати йому. Для кількох серверів потрібне спільне сховище блокувань. `retry_after` черги має перевищувати `timeout=75`; стандартне значення конфігурації проєкту — 90 секунд. Робочі черги та `.env` іншого агента не змінюються.

У формі власник задає ID доступної GPT-моделі, окремий API-ключ і правила магазину, а потім дозволяє ручні чернетки. Модель навмисно не обирається автоматично. Альтернатива для секрету та ID моделі — окремі змінні `GPT_DRAFT_API_KEY`, `GPT_DRAFT_MODEL`. Налаштування наявного агента не читаються. Після зміни конфігурації слід перезапустити відповідний обробник черги.

Таблиці `gpt_settings`, `gpt_dialogues`, `gpt_runs` містять лише службові дані GPT. Ключ зашифрований Laravel; він не повертається клієнту, не додається до журналу генерації та не передається назад через помилки провайдера. Усі сторінки й API доступні тільки активному власнику; тестові діалоги додатково обмежені їх автором.

Для постійної роботи на сервері передбачено окремий процес Supervisor у `scripts/supervisor-domcrm-gpt-drafts.conf`. Він обробляє тільки `gpt-drafts`; наявні процеси черг не змінюються.

## Джерела

- Опис і прив’язки модельної лінійки: `ai_photo_groups`, `ai_photo_group_product`.
- Фото та позначені товари: `ai_photos`, `ai_photo_product`. Нерозмічені фото, пояснення розмірів, сторонні шляхи та фото з некоректними прив’язками відкидаються; пояснення не видаються за фото кольору.
- Ціна продажу, валюта, артикул, колір, категорія: наявний каталог `products`, `colors`, `categories`.
- Розміри та залишки: активні `product_variants`. За наявності варіантів загальний запас обчислюється з них; для товару без варіантів використовується його власний залишок.
- Умови магазину задаються власником окремо. Відсутні умови потребують уточнення.

Закупівельна ціна, собівартість, токени Meta та дані робочих чатів не входять до даних моделі. Галерея й товари читаються напряму, без дублювання чи зміни їх таблиць. Власник вводить тестові повідомлення вручну; не слід вставляти зайві персональні дані.

## Перевірки результату

GPT може лише шукати моделі, отримувати презентацію групи та перевіряти пропозицію товару. Немає інструментів запису в CRM. Пропозиції й фото повинні бути отримані в поточній обробці та належати до вибраної групи; для конкретного товару дозволені лише його окремі фото.

Модель створює короткий текст без чисел і URL. Сервер додає ціну, валюту, артикул і наявність за повторно прочитаними даними. Отже, застаріла ціна з історії не переноситься до картки. Це технічна перевірка посилань і числових фактів; властивості в описовому тексті все одно потребують оцінки власником у режимі чернеток.

Використовується `store: false`, власна обмежена історія тестових діалогів та строгі схеми інструментів/результату. За одну обробку дозволено до чотирьох запитів до моделі та восьми викликів інструментів, із загальним лімітом часу та контексту. Протокол реалізовано за офіційною документацією [function calling](https://developers.openai.com/api/docs/guides/function-calling) та [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

Завдання й ручні HTTP-запити ідемпотентні. Помилки зберігають початкове повідомлення, а невдала генерація не змінює пам’ять діалогу. Повтор після невизначеного результату HTTP-запиту використовує попередній UUID, щоб уникнути подвійної генерації. Повтор після підтвердженої помилки — новий запуск, який може повторно витрачати токени.

## Перевірка локальних даних без виклику OpenAI

```sh
php artisan gpt:inspect-catalog
php artisan gpt:inspect-catalog --group=ID
```

Команда виконує лише читання наявної галереї. Вона не потребує службових таблиць GPT, не створює чернеток і не викликає зовнішніх API.

## Автотести

```sh
APP_ENV=testing DB_CONNECTION=sqlite DB_DATABASE=:memory: APP_CONFIG_CACHE=/tmp/domcrm-gpt-test-config.php vendor/bin/phpunit tests/Feature/Gpt
npm test -- resources/js/crm/pages/settings/GptDraftsPage.spec.js
```

Тести використовують наявні моделі товарів, кольорів, розмірів і галереї з тестовими записами в ізольованій SQLite-базі. OpenAI замінено HTTP-фікстурами, сторонні мережеві звернення заборонені. Перевіряються права, шифрування, актуальність ціни, відповідність фото, межі інструментів, збереження помилок і відсутність змін робочих чатів/замовлень. Перевірка реальної якості GPT потребує окремого ключа, вибраної моделі та ручного перегляду чернеток.
