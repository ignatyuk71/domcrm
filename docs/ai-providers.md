# Перемикач Claude API / ChatGPT API

У `/settings/ai` є **один активний API для всієї CRM**: Claude або ChatGPT (OpenAI). Вибір застосовується після натискання «Зберегти» та керує відповідями агента, підсумками чатів і класифікацією постів для автовідповідей на коментарі.

Обидва ключі й обидві моделі зберігаються окремо. Перемикання не видаляє налаштування іншого API. За замовчуванням використовується Claude; збереження ключа OpenAI саме собою не активує його. Для вибраного API потрібен його ключ.

## Розгортання

1. Перед активацією нового коду застосуйте лише нову міграцію:

   ```sh
   php artisan migrate --path=database/migrations/2026_10_26_120000_add_openai_provider_to_ai_settings.php --force
   ```

   Вона додає nullable-поля. Наявний ключ Claude, його модель і поточні налаштування не переписуються. Цільовий `--path` не запускає сторонні незастосовані міграції.

2. Зберіть фронтенд через `npm run build` і розгорніть код разом зі зібраними файлами. Якщо реліз використовує кеш маршрутів/представлень, оновіть його звичайним процесом деплою.
3. Відкрийте `/settings/ai` під власником. Активним лишається Claude API.

## Використання

1. У блоці ChatGPT API введіть ключ OpenAI та ID доступної моделі. Початкове значення — `gpt-6.1-sol`.
2. «Перевірити» перевіряє ключ і доступ до моделі через `GET /v1/models/{model}` без генерації та без перемикання системи.
3. Виберіть **ChatGPT API (OpenAI)** у перемикачі та збережіть. Усі нові відповіді агента використовуватимуть OpenAI.
4. Щоб повернутися, виберіть **Claude API** та збережіть. Збережений ключ Claude використається автоматично.

Порожні поля ключів зберігають попередні значення. Обидва ключі зашифровані й не повертаються браузеру. Налаштування підключення доступні лише власнику.

## Реалізація

- `AiClient` читає провайдера лише з глобального рядка `AiSetting`. Окремого провайдера на магазин немає.
- `AiSession` фіксує API, ключ і модель на поточний хід. Відповідь, яка вже генерується, завершується через той API, з яким почалася. Зміна перемикача застосовується до наступних ходів.
- `ClaudeClient` лишився без змін. `OpenAiClient` адаптує спільну історію, зображення й інструменти до Responses API. Правила спілкування та бізнес-інструменти спільні.
- OpenAI використовує `store: false`; контекст зберігає CRM. Початкові `call_id` і зашифровані reasoning items повертаються в наступні кроки поточної відповіді.
- Інструменти мають strict JSON Schema; необов'язкові поля дозволяють `null`. Паралельні виклики вимкнені. Інструменти з незавершеної відповіді або з некоректними аргументами не виконуються.
- Для GPT-6 встановлено reasoning `low` та бюджет щонайменше 4096 вихідних токенів. Нові моделі з іншими параметрами потрібно перевіряти перед перемиканням.
- Автоматичного переходу на інший API при помилці немає. Чинний `ai:sweep` повторює невдалу обробку за своїми правилами.
- У `ai_runs` додано `provider` і `model` для аналізу відповідей, помилок, токенів та часу виконання.
- Фіксація заявки й передача її менеджеру працюють за чинним сценарієм.

Офіційні джерела: [Responses API](https://developers.openai.com/api/docs/guides/migrate-to-responses), [інструменти](https://developers.openai.com/api/docs/guides/function-calling), [зображення](https://developers.openai.com/api/docs/guides/images-vision), [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol). Автоматичні тести підміняють API; живе підключення перевіряється власним ключем у налаштуваннях.
