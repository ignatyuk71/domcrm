# 📋 ТЗ: Історія замовлень клієнта на сторінці створення замовлення

## 1. Мета
Коли менеджер обирає **існуючого клієнта** й натискає «Готово» (блок клієнта згортається), **одразу під ним** показати **історію його замовлень** із кольоровими статусами CRM — щоб ще до оформлення бачити, **чи клієнт забирає посилки**. Багато хто замовляє і не викуповує — це фільтр надійності.

## 2. Де
- `OrderCreatePage.vue` (створення) і `OrderEditPage.vue` (редагування)
- Новий блок **під** `CustomerBlock.vue`

## 3. Коли
- Тільки для існуючого клієнта — коли встановлено `local.id` (`CustomerBlock.vue:300`, `applyCustomer()`).
- Новий клієнт (`local.id == null`) — блок ховаємо.

## 4. Що показувати по кожному замовленню
- **Товар коротко:** назва + розмір + ціна → `Домашні тапочки, 36-37, 399 ₴` (з `items[].product_title / size / price`)
- **Дата** (`created_at`)
- **Кольоровий бейдж статусу** — назва + фон (п.5)

## 5. Статуси — з готових статусів CRM (НЕ робимо нові)
Джерело — **`order.status_ref`** (`name`, `color`, `icon`), що вже віддає бекенд.
**Колір беремо живий із `status_ref.color`** — не хардкодимо (статуси редагуються в CRM, сідер застарів).

Ключові для мети «забрав / не забрав»:

| Статус (код) | Сенс | Роль у підсумку |
|---|---|---|
| Успішно завершено (`delivered_paid`) | забрав і оплатив | 🟢 **забрав** |
| Прибуло у відділення (`delivered`) | лежить у відділенні | 🟡 **у відділенні** |
| Повернення (`returned`) | не викупив | 🔴 **повернув** |
| Відправлено (`shipped`) | в дорозі | в дорозі |
| Новий / В обробці / Підтверджено / Упакування / Запаковано | ще в роботі | в обробці |

Текст і колір бейджа — як у CRM (через `status_ref`). Окремо НП-статус доставки **не чіпаємо** — обходимось статусами замовлення.

## 6. Індикатор надійності (зверху над списком)
> **Забрав 6 · Повернув 3 · % викупу 67%**

Рахунок на фронті по списку: `delivered_paid` → забрав; `returned` → повернув; `% = забрав / (забрав + повернув)`.

## 7. Джерело даних (вже існує ✅)
- `GET /customers/{id}` → `CustomerController::show()` (`CustomerController.php:65-114`) повертає `recent_orders` (ліміт 10) з `items`, `status_ref:id,code,name,icon,color`, `items_sum_total`, `created_at`, `currency`.
- **Бекенд міняти не треба.**

## 8. Технічна реалізація (фронт)
- Новий компонент **`CustomerOrderHistory.vue`** під `CustomerBlock`.
- Тригер: watcher на `local.id` → `GET /customers/{id}` → рендер.
- Розмітку взяти з **`CustomerQuickView.vue:143-168`** (карточки історії готові).
- **Єдина доробка:** бейджу застосувати **фон `order.status_ref.color`** (зараз у `CustomerQuickView` колір не використовується — білий фон, `:810-818`). Текст — `status_ref.name`, іконка — `status_ref.icon`.

## 9. Поведінка
- 0 замовлень → «Перше замовлення, історії ще немає».
- Завантаження → спінер.
- Замовлення клікабельні (нова вкладка) — як у `CustomerQuickView`.
- Блок довідковий, форму не блокує.

## 10. Поза рамками
- Нові статуси НЕ створюємо — використовуємо наявні CRM-статуси з бази.
- Бекенд не міняємо.
